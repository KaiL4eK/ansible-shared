# PostgreSQL schema through Kubernetes Job

Применяет идемпотентные SQL-выражения (схема приложения) короткоживущим
Kubernetes Job. PostgreSQL server не устанавливается: Job подключается к
заданному Service/DNS имени под учёткой приложения. Пин образа по умолчанию —
официальный `postgres:17.6-bookworm`.

Все параметры объявлены в `defaults/main.yml`, префикс `k8s_postgresql_schema_`.
Поддерживается только режим управляемых credentials: плейбук передаёт
`k8s_postgresql_schema_user` и `k8s_postgresql_schema_password` из своего Vault,
роль сама проверяет входы и существование namespace, создаёт уникальный
временный Secret и Job, ждёт результат и удаляет Secret в `always`, в том числе
при ошибке. `k8s_postgresql_schema_job_name` служит префиксом (до 34 символов);
фактические имена Secret и Job генерируются сервером и уникальны для каждого
запуска. Check mode отклоняется. Namespace должен существовать заранее.
Необязательный `k8s_postgresql_schema_kubeconfig` позволяет проверить наличие
явно выбранного файла без чтения; подключение использует стандартные
`K8S_AUTH_*`.

Пароль Job получает через `secretKeyRef`; значения не попадают в Job spec или
логи. SQL-выражения передаются списком `k8s_postgresql_schema_statements`
(без завершающих `;` — роль нормализует), склеиваются через `;` в один `psql`
вызов с `ON_ERROR_STOP`; ошибки SQL завершают Job с ошибкой. Выражения должны
быть простыми DDL без внутренних `;` в строковых литералах и
dollar-quoted блоках. Выражения не являются секретом и видны в Job spec.
Для идемпотентных повторных запусков выражения должны использовать
`CREATE ... IF NOT EXISTS`; расхождения существующей схемы роль не выправляет.

Операции с Secret скрыты через `no_log: true`, `diff: false`. Роль ждёт
`Complete` или `Failed` и завершает play с ошибкой при неуспехе. Job
автоматически очищается TTL-контроллером через 10 минут, Pod не получает
ServiceAccount token. Нужны права на Job и чтение его статуса, а также
создание/удаление Secrets в целевом namespace. Пользователь должен иметь право
создавать объекты в целевой схеме (обычно — owner БД, как выдаёт
`k8s/postgresql_init_db`).
