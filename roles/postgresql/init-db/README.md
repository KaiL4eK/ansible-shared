# Инициализация PostgreSQL напрямую

Создаёт только отсутствующих пользователя и БД. Существующие пароль, атрибуты
пользователя и владелец БД не изменяются. При другом владельце БД роль падает.

Пароль приложения (`postgresql_init_db_user_password`) обязателен; значения
пароля приложения и администратора, похожие на заглушки
(`CHANGE_ME`/`dummy`/`placeholder`, набор настраивается
`postgresql_init_db_password_placeholder_regex`), отклоняются до любых
подключений к PostgreSQL — проверка выполняет сама роль, consumer-плейбуку
дублировать её не нужно.

После создания пользователя (либо сразу для существующего) роль проверяет
подключение с application credentials к `postgresql_init_db_admin_database`
(по умолчанию `postgres`). При ошибке аутентификации выполнение прекращается
до создания БД; пароль не сбрасывается. Это относится и к режиму без admin
credentials: пользователь в этом случае уже должен существовать и для создания
новой БД обладать CREATEDB.

Проверочной БД нужен CONNECT для application user. PostgreSQL должен проверять
пароль: дополнительный вход с заведомо неверным паролем обязан отклоняться.
`trust` и другие методы без проверки пароля приводят к ошибке bootstrap.
В check mode новая роль/БД не создаётся; проверка credentials отсутствующего
пользователя пропускается. Для существующего пользователя выполняются read-only
проверки подключения.

Credentials скрыты через `no_log`. Ротация пароля выполняется отдельной
операторской процедурой, не повторным запуском этой роли.
